# Excel Dashboard HTML

将 Excel 数据转换成清晰、专业、有设计感的交互式 HTML 数据看板。

**用户想看什么 → 数据里什么值得看 → 应该怎么呈现 → 生成看板。**

不要读取 Excel 后直接堆图表，不要把 Excel 简单搬到网页上。

## 1. 理解数据与分析目的

先读取工作簿，理解 Sheet、字段、时间粒度、分类、数值、单位及指标关系。使用环境中可用的电子表格读取工具；若有 spreadsheets skill，按其要求读取和检查工作簿。

- 区分明细、汇总和小计，防止重复累计；检查日期、空值、重复记录和公式结果。
- 不修改原始数据含义，不虚构缺失值；缺失与零分开处理。
- 公式缓存缺失或可疑时，先用可用工具重算或核实，不能把缺失缓存当作零。
- 明确比率的分母、增长的比较基期、币种和单位；比率优先用汇总后的分子与分母计算，不能直接平均各行百分比。

生成看板前明确用户要解决的问题，例如核心指标、趋势、增长下降、业务对比、占比、目标完成或异常排查。

用户已经明确目的时不要重复询问。没有明确目的时，只用一个简短问题让用户选择最关注的方向；等待期间可继续检查数据。没有提供数据时请求文件，不用虚构数据替代真实数据制作风格预览。

### 生成前询问页面形式

在生成任何 HTML 风格预览或完整看板之前，先询问：

> 你希望看板采用哪种页面形式？
>
> 1. **可纵向滚动的单页面看板**：所有模块放在同一个页面，向下滚动浏览，适合连续阅读和整体分析。
> 2. **导航切换多个横向页面**：按主题拆成多个横向布局的页面，通过顶部或侧边导航切换，适合分主题查看与讲解。

如果分析目的也未明确，将两个问题一起提出。用户已明确页面形式时直接采用，不重复询问；用户明确授权自行决定时，可结合数据选择并说明。否则等待用户选择，不默认生成长页面；等待期间继续数据检查与分析。

选择多页面后，根据分析主题提出合理的页数和页面名称，让用户确认或调整；用户已指定页数、结构或授权自行安排时按其要求执行。两种形式都可封装在一个独立 HTML 文件中，不能把“单文件”理解为“只能单页面”。

## 2. 分析什么值得看

先分析，再选择图表。寻找：

- **↑ 明显增长**：哪些指标、产品、地区、渠道或时间段增长明显？
- **↓ 明显下降**：哪些数据明显下降或持续下滑？
- **⚠ 异常**：哪些数据突增、突降、偏离基准或波动异常？
- **◎ 值得关注**：结构变化、贡献集中、目标差距等是否值得进一步分析？
- **？可能存在的问题**：多个指标组合是否提示需要进一步检查的问题？

例如，总销售额上升时仍可发现某地区销售额下降、线下渠道下滑和退款率上升，但每项都必须有数据支持。不要把同时发生解释为因果关系。

增长与下降同时考虑绝对量、相对变化、样本量、时间跨度和基期。基期为零时说明“新增”或“无法计算增长率”，不展示 Infinity。区分百分比变化与百分点变化。不夸大普通波动；异常标记需有可说明的基准或规则，无足够依据时称为“值得关注的变化”。

在工作记录中保留指标口径、比较范围、来源 Sheet / 字段和重要数据限制。界面通过简短说明或 Tooltip 提供必要口径，不把处理过程铺满页面。

## 3. 确定重点与图表

默认视觉优先级：核心指标 → 明显增长 / 下降 → 异常 → 值得关注的变化 → 有依据的待查问题 → 普通数据。根据用户目的调整，避免所有指标视觉权重相同。

| 数据要说明什么 | 默认呈现 |
| --- | --- |
| 核心结果 | KPI / 大数字 |
| 时间变化 | 折线图 |
| 分类比较 | 柱状图 |
| 排名 | 横向条形图 |
| 占比 / 结构 | 少量类别用饼图或环形图，更多类别优先堆叠图或条形图 |
| 目标完成 | 进度条及实际值、目标值 |
| 具体记录 | 可排序、筛选的表格 |

一个数字能说清楚时不强行画图。图表标明单位、时间范围和比较口径；柱状图以零为基线，折线图如使用非零基线须清楚显示刻度。缺失时间点不能伪装为零，排序和连接方式不得制造趋势。

### 图表类型多样性

看板中的主要分析模块应尽量使用多样的图表表达，不要全靠 KPI 数字、文字环比或同一种折线图。根据数据含义组合折线图、柱状图、横向条形图、饼图 / 环形图、进度条、小型趋势图和表格，让不同问题有不同视觉形态。

环比、同比、完成率、结构占比和效率变化等指标，优先用小图表辅助表达，而不是只写一个百分比。例如：

- 环比变化 → 小型柱状图、正负条、瀑布式变化条或前后对比条。
- 平台 / 类别贡献 → 柱状图、横向条形图或帕累托式排行。
- 内容类型、平台结构、状态分布 → 饼图 / 环形图或 100% 堆叠条；类别过多时改用条形图。
- 完成率、目标差距 → 进度条、仪表式进度或目标线柱状图。
- 效率变化 → 趋势线配合环比变化条，或用小倍图比较制作时长、修改占比、按时交付率。

同一页内图表类型要服务阅读节奏：核心趋势可以用折线，分类对比用柱状或条形，结构用饼图 / 环形图，目标用进度，明细用表格。不要为了“多样”使用不适合数据的图表；饼图只适合少量互斥类别，且各部分应能组成清楚整体。

## 4. 设计分析交互

只为真正有分析价值的维度提供筛选、切换、比较和详情，例如时间、地区、渠道、产品。不把每列都做成筛选器。

使用统一筛选状态和同一份派生数据更新 KPI、图表、异常提示、比较结果及明细。比较对象采用相同口径和可比时间范围。切换后重新计算洞察，不能沿用全量数据的固定文案。

当页面展示环比、同比、排名、完成率或结构占比时，筛选和切换后相关的小图表也要同步重绘。例如“内容与效率”这类页面，不应只列出环比文字；制作时长、修改占比、AI 辅助数和按时交付率等变化应尽量配合小柱图、进度图、对比条或环形进度表达。

提供当前筛选状态、重置入口、无结果状态及必要的加载反馈。没有适合切换或比较的维度时，不制造无意义控件，并在交付时说明。

## 5. 融合 Frontend Slides 的设计方法

本节已将 frontend-slides 的设计原则融合为 Dashboard 工作流，可独立使用。借鉴其视觉探索与设计系统，不启动幻灯片制作流程。

### 设计原则

- **Distinctive Design**：根据业务、受众和数据特征形成明确视觉方向，避免通用卡片模板。
- **Typography**：用有特色的标题字体与清晰的数据字体建立层级。中文字体须覆盖中文；数字优先使用等宽数字特性 `font-variant-numeric: tabular-nums`。不要反复默认使用 Inter、Arial 或 Space Grotesk。系统字体可作可靠回退。
- **Color & Theme**：用 CSS variables 统一色彩、字体、间距和组件。使用主色与少量重点色，保持系列颜色稳定。增长下降不一定等于好坏，例如成本增长需结合业务含义；颜色同时配合符号或文字。
- **Visual Hierarchy**：让核心结果和异常有明显但克制的视觉权重，不靠缩小文字塞入全部数据。
- **Motion**：用有节奏的首次呈现、数据增长和状态过渡帮助理解。简单状态优先 CSS，数值插值与图形绘制按需使用原生 JavaScript。
- **Background**：用留白、细线、轻量几何或渐变建立层次，保证图表绘图区干净、对比度充足。
- **Show, Don't Tell**：通过真实可打开的预览帮助用户选择风格，不只给抽象描述。
- **Progressive Disclosure**：先看轻量风格索引，只在选定风格后读取详细设计配方。

避免所有内容套圆角卡片、白底紫色渐变、过度玻璃效果、满屏图表、无意义装饰，以及为了视觉效果牺牲可读性。

### 三种真实数据首页预览

先确定页面形式，再进行视觉探索。用户没有明确视觉方向时，按照所选页面形式，用同一份真实 Excel 数据、相同指标口径和核心信息生成三个自包含 HTML 首页预览：

1. **稳健方案**：克制、清楚、适合日常分析。
2. **鲜明方案**：有明显字体、构图或色彩个性，但保持专业可读。
3. **定制方案**：依据业务特征设计，与前两者形成有用差异。

三个方案在布局、字体、KPI、图表视觉、背景或组件组织上有实质区别，不能只换颜色。每个预览展示真实首页，包含核心指标、至少一个有意义的动态图表和代表性的筛选区域，而非只做标题封面。

若本机可用 frontend-slides 的资源，可在其技能目录内：

- 先读 `STYLE_PRESETS.md`；若存在，再读 `bold-template-pack/selection-index.json`。
- 根据 mood、tone、formality、density、scheme、best_for 和 avoid_for 选择候选，仅阅读候选的 `preview.md`，提取视觉语言并改造成真实看板首页。
- 通常组合一个稳健预设、一个合适的鲜明模板和一个自定义方向；模板不合适时自主设计，不强行套用。
- 用户选定后，仅阅读对应的 `design.md`。仅当关键实现细节缺失时才参考 `template.html`。

这些外部文件是可选灵感，不是运行依赖；缺失时按本节自行设计三种方向。

保存至当前项目 `.excel-dashboard-html/previews/style-a.html`、`style-b.html`、`style-c.html`，打开供用户查看，随后请用户选择或说明如何融合。选择前不擅自确定完整看板的风格；若用户明确授权自行选定，则自主选择并说明。

页面内只放真实业务内容、标题、时间范围、筛选及数据。风格名、A/B/C 标签、模板名、文件路径、“预览”“AI 生成”等过程元数据放在交付消息中，不放入看板。

用户已有品牌规范、视觉参考、明确方向或要求保留现有设计时直接应用，不重复走三方案选择。

### 扩展选定的设计系统

保留选定方案的字体、配色、间距节奏、网格、装饰语言和组件规则，将其扩展至明细表、Tooltip、Tabs、筛选器、空状态和详情面板，不中途切换模板。

看板按用户选择采用以下布局：

- **纵向滚动单页**：模块按信息层级纵向组织，支持自然滚动、锚点导航和渐进展开。
- **导航切换多个横向页面**：按确认的主题与页数组织，桌面以横向宽屏 Dashboard 画布呈现，每次显示一个页面。默认使用顶部导航或轻量页签标明当前位置，不使用占据左侧空间的侧边导航栏，除非用户明确要求侧边栏。切换页面时保留筛选状态，明确全局筛选与页面局部筛选的作用范围。不要把多页重新拼成长页面；不强制固定比例、全屏缩放或左右滑动。内容过多时调整分区或页数，明细区域可局部滚动。

多页面桌面端应优先设计成“一页一屏”的 Dashboard 画布：常见目标视口按 1440×900 或接近尺寸验证，单个页面的主要信息应在当前视口内完整可见，不需要页面级上下滚动。为此应控制顶部导航、标题区和说明文字的高度，标题使用 Dashboard 级别字号，不要用幻灯片式超大标题抢占数据区域。若一页内容确实超出，应先减少装饰、压缩标题、合并文案或拆成更多主题页，而不是让页面自然长滚动；只有明细表、日志列表等局部内容可在自身容器内滚动。

页面空间分配要跟数据量匹配。数据不多的页面不能留下大片空白，应通过均衡网格、小倍图、目标进度、结构图、环比变化条、趋势小图、注释或口径说明把页面组织成视觉重量接近的板块。例如“平台表现”不只放一个条形图和一句解释，可同时呈现平台贡献结构、环比变化、新增粉丝和完读表现；“社群与目标”可同时呈现社群趋势、运营变化、目标进度和响应效率。不要为填空而虚构指标；只能用已有数据派生有意义的辅助视图。

两种形式均采用响应式布局。手机重排列数和控件，允许当前页面按需纵向滚动；多页面仍保留导航切换。手机端不要为了“一页一屏”强行缩小到不可读。宽表可在自身容器内横向滚动。

不继承 Frontend Slides 的固定 1920×1080 舞台、固定 16:9、演讲用逐页翻页机制、演讲者页面结构或禁止滚动规则；多页面使用 Dashboard 自身的主题导航。不导入 `viewport-base.css`；不照搬幻灯片导出、部署、快捷键或行内文字编辑流程。

## 6. 组织 Dashboard 信息层级

- **第一层：核心结果**。首页突出核心 KPI、重要增长下降及异常，展示必要的时间范围和比较基准。
- **第二层：趋势与比较**。展示时间趋势、分类比较、排名、结构变化和目标完成。
- **第三层：详细数据**。通过 Table、Tabs、Detail Panel、展开和 Tooltip 查看具体记录与口径。

默认便于持续阅读和分析；通过层级与按需展开控制密度，不把全部 Excel 数据平铺首页。Tooltip 不能成为触屏或键盘用户获取关键数据的唯一方式。

## 7. 鼠标光圈规则

使用自定义光圈时，光圈必须替代系统鼠标指针，不能两个同时出现。数字 Hover 放大变色可以保留。

- 只在支持精细鼠标和 Hover 的设备启用，触屏不显示。
- 光圈成功创建并能响应指针后，才给页面或指定区域添加启用类，在该范围及其所有后代设置 `cursor: none`，包括按钮、链接、输入框和图表，防止 Hover 时箭头重新出现。
- 光圈设置 `pointer-events: none`，不拦截点击、拖动、滚动或 Tooltip，不遮挡数字。
- Hover 放大用 transform 等不影响布局的方式，颜色保持可读。
- 离开窗口、失焦或停用时隐藏光圈并移除启用类；重新进入且就绪后再启用。初始化失败或已检测到的运行故障也移除启用类，恢复系统指针。
- 不对浏览器原生弹窗等不可控区域承诺隐藏系统指针；进入这类交互时停用自定义光圈，避免双指针。
- 保留键盘焦点指示。减少动态效果模式下禁用光圈拖尾，必要时恢复原生指针。

## 8. 动态图表规则

主要数据图尽量有清晰的增长、绘制或变化过程，而非只显示静态结果。

| 元素 | 首次呈现 |
| --- | --- |
| 柱状图 / 条形图 | 从零基线增长至真实值，负值向负方向延伸 |
| 折线图 | 沿时间顺序从左向右绘制，保留缺失值断点 |
| 进度条 | 从 0 填充到真实比例；超过目标时如实显示完成率，并明确表现超额部分 |
| KPI / 大数字 | Count Up，从初始值递增或递减到真实值，保留单位、符号和小数位 |
| 饼图 / 环形图 | 克制的扇区展开或渐显，不改变真实比例 |

首次进入可视区域才播放，默认只播放一次，不因普通 Hover 或反复滚动重播。可用 IntersectionObserver 控制入场，数值插值用 requestAnimationFrame；一般持续约 400–900 ms，错峰延迟保持短暂。

筛选、切换或比较变化后，从当前显示状态平滑过渡到新状态，不必每次归零；类别变化按稳定标识匹配，无法合理插值时使用淡入淡出。取消旧动画或使用更新版本标记，连续操作以最新选择为准，不让旧动画覆盖新数据。

最终数值、比例、坐标轴、Tooltip 和明细必须来自同一份真实计算结果；动画中间值只用于视觉，不参与计算或生成洞察。不通过弹跳、夸张缩放或动态改变坐标尺度制造增长感。动画不阻塞筛选或查看详情。

保留适度的 Tab 切换、Hover、Tooltip 和异常短暂强调，避免持续运动、循环闪烁。支持 `prefers-reduced-motion`，启用时直接显示最终数据；打印或静态导出也必须呈现最终状态。

## 9. 实现与输出

默认生成一个可直接打开、无需构建环境的独立 HTML，内部使用用户选定的单页或多页面结构：

- CSS、JavaScript 和所需数据内联，优先原生 HTML / SVG / Canvas 实现图表，无 CDN 或联网运行依赖。
- 字体可使用许可允许嵌入的字体；没有可用字体时使用合适的本地字体栈与回退。不能让 Google Fonts 等外部请求成为离线可读的前提。
- 统一 CSS variables 管理主题；按数据、派生计算、渲染、交互、动画分区并添加清晰注释。
- 数据读取时保持原文件不变；只嵌入完成看板所需数据。数据作为安全序列化的数据载入，工作表文本用 textContent 等安全方式呈现，避免内容被当作 HTML 执行。
- 支持有分析价值的筛选、指标切换、比较和明细，所有相关区域同步更新。
- 数字格式、单位、空值、负值和精度一致；控件有标签，支持键盘操作和可见焦点。

修改已有 Dashboard 时先理解原有数据口径、状态和设计系统，再完成用户要求的改动，不无故重做风格选择或覆盖无关成果。

## 10. 验证与交付

交付前用真实数据核对至少一个总量指标、一个比率或增长指标（如存在），以及一个筛选后的结果；核对明细与聚合一致。

在浏览器中检查桌面（例如 1440×900）和手机（例如 390×844）截图，确认无重叠、截断、不可读文字或页面级意外横向溢出。不能只用 scrollHeight 判断视觉正确性。

检查真实交互：筛选、重置、切换、比较、空结果、详情，以及连续快速筛选。确认没有报错，离线打开可用；验证鼠标经过按钮、链接、数字和图表时不出现双指针，减少动态效果时数值完整可见。

若环境无法执行浏览器验证，明确说明哪些项目尚未验证，不声称已通过。

最终检查：

- 生成前是否已询问页面形式，最终结构是否符合用户选择？多页面的页数与主题是否已确认或获授权自行安排？
- 用户最想看的问题是否得到回答，是否先分析再绘图？
- 增长、下降、异常和待查问题是否有数据依据，是否避免虚构原因与结论？
- 图表是否适合数据，视觉权重是否明确，是否存在图表堆砌？
- 主要页面的图表类型是否足够多样，环比、结构和目标是否尽量用合适的小图表表达，而不是只写数字？
- 多页面桌面端是否采用顶部导航或轻量页签，避免默认侧边导航占据数据空间？
- 多页面桌面端是否做到每页主要 Dashboard 内容一屏可见，标题区是否为数据区域留出足够空间？
- 数据较少的页面是否通过均衡布局和有依据的辅助图表减少大面积空白？
- 三种预览（如需要）是否使用相同真实信息且有实质设计差异？
- 风格是否统一、专业，手机布局是否仍然可读？
- 交互和动态更新是否帮助分析，数据和洞察是否同步？
- 自定义光圈是否完全替代系统指针，并有恢复机制？
- 图表是否有适合类型的动画，并准确停在最终值？

打开最终 HTML，并提供文件链接，简述分析重点、主要交互和已知数据限制。发布或导出仅在用户要求时执行，不自动上传数据。保留用户原始数据和已有产物；不为清理预览删除非本次生成的文件。

最终看板应让用户快速完成：**看结果 → 看变化 → 找异常 → 进一步筛选分析**。
